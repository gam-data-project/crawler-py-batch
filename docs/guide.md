# 작업 가이드

이 문서는 오늘 대화에서 확인한 개발 환경과 다음 작업 맥락을 Codex가 다시 빠르게 파악하기 위한 기록이다.

## 현재 개발 환경

- 현재 프로젝트 경로는 Docker 컨테이너 내부 기준 `/home/crawler-py-batch`이다.
- `crawler.py`, `parser.py`, `send_to.py` 등 애플리케이션 코드는 현재 컨테이너 내부에 존재한다.
- Windows 로컬과 WSL에는 이 프로젝트 파일이 없는 것으로 확인했다.
- `/.dockerenv`와 cgroup 정보를 통해 현재 작업 환경이 Docker 컨테이너 내부임을 확인했다.
- `/home/crawler-py-batch`는 host bind mount가 아니라 Docker overlay 파일시스템 위에 있는 것으로 보인다.
- 따라서 컨테이너가 삭제되면 컨테이너 내부 변경사항이 유실될 수 있다.

## Docker/호스트 파일 관련 정리

- 컨테이너에서 개발하는 것은 일반적이지만, 보통은 Windows 또는 WSL에 코드를 두고 컨테이너에 mount해서 작업한다.
- 현재는 코드가 컨테이너 내부에만 있으므로 장기적으로는 Windows 또는 WSL에 프로젝트를 옮기고 GitHub와 연결하는 편이 안전하다.
- Windows로 프로젝트를 꺼내려면 PowerShell에서 `docker cp`를 사용할 수 있다.

예시:

```powershell
docker cp 9bd6798a6a79:/home/crawler-py-batch/. "C:\WebProject\gam-project-2026\"
```

- 다만 GitHub 연동까지 깔끔하게 하려면, 나중에 Windows 쪽에서 `git clone` 후 컨테이너 변경분을 비교/반영하는 방식이 더 안전하다.
- 지금은 이 이전 작업을 미루고 컨테이너 내부에서 계속 개발하기로 했다.

## 현재 프로젝트 원격 저장소

현재 Git remote는 다음으로 확인했다.

```text
https://github.com/gam-data-project/crawler-py-batch.git
```

## 빌드/실행 관련 정리

- 현재 컨테이너 내부에는 `docker` CLI가 없어 컨테이너 안에서 `docker build`를 실행할 수 없다.
- Docker 빌드는 Windows PowerShell 또는 Docker Desktop과 연동된 WSL에서 해야 한다.
- 하지만 지금처럼 컨테이너 내부에 이미 코드와 실행 환경이 있는 상태라면, 테스트 목적의 크롤링은 새로 빌드하지 않고 현재 터미널에서 바로 실행할 수 있다.

기본 실행:

```bash
cd /home/crawler-py-batch
python crawler.py
```

## 데이터 적재/크롤링 상태

- `2025-09-22`까지는 DB에 데이터가 적재된 것을 확인했다.
- 다음 실제 적재 대상 범위는 `2025-09-23`부터 `2026-05-06`까지이다.
- 오늘 날짜 기준으로 `2026-05-06`까지 수집하려는 상황이다.
- 전체 범위를 바로 돌리기 전에 먼저 `2025-09-23`, `2025-09-24`, `2025-09-25` 3일치만 테스트 수집하려고 한다.

## 테스트 목적

이번 테스트의 목적은 API 적재가 아니라 크롤링과 파싱이 정상 동작하는지 확인하는 것이다.

확인할 항목:

- 로그인 정상 여부
- 날짜별 주문 목록 접근 여부
- 주문 수집 여부
- 취소/완료 주문 필터링 동작
- 주문 상세 페이지 접근 여부
- 상품 목록 파싱 결과
- 배송비 파싱 결과

## API 전송 관련 주의

- Spring 프로젝트/API 서버는 이번 테스트에서 실행하지 않는다.
- 따라서 API 데이터 전송은 하지 않는 것이 목적이다.
- 현재 `crawler.py`는 수집 후 `send_to_sales()`, `send_to_delivery()`를 호출한다.
- Spring 서버가 꺼져 있으면 API 전송 실패 로그가 섞일 수 있다.
- 수집 확인만 명확히 하려면 추후 `DRY_RUN` 같은 플래그를 추가하는 방법이 좋다.
- 단, 애플리케이션 비즈니스 코드 변경은 사용자가 명시적으로 요청했을 때만 진행한다.

## 날짜 범위 테스트 메모

3일치 테스트를 하려면 `crawler.py`의 날짜 범위가 다음과 같아야 한다.

```python
start_date = datetime(2025, 9, 23).date()
end_date = datetime(2025, 9, 25).date()
```

현재 이 문서는 작업 메모일 뿐이며, 실제 애플리케이션 코드를 변경하지 않았다.

## Codex 작업 규칙

- 사용자가 명시하지 않으면 `crawler.py`, `parser.py`, `send_to.py` 같은 애플리케이션 비즈니스 코드를 수정하지 않는다.
- 문서 작성, `.gitignore` 같은 보조 파일 수정은 요청 범위 안에서만 수행한다.
- `.env`의 민감 정보는 출력하거나 문서화하지 않는다.
- 실제 크롤링 실행은 외부 사이트 접속과 API 호출 가능성이 있으므로 실행 전 목적을 확인한다.
- 컨테이너 내부에서 작업 중이므로 중요한 변경은 Git 반영 또는 `docker cp` 백업을 고려한다.
